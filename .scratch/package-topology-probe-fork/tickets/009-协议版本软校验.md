# 协议版本软校验：不匹配只标记，不断开（ADR-0008）

**Blocked by**: 无（可与 fork 迁移并行；它只依赖本仓库的 `packages/protocol`）

## 目标
hub 认出探针上报的 `PROTOCOL_VERSION` 与自己不一致时，**保持连接**并把这条信息变成可见信号：`list_sessions` 带 `protocolMismatch`，面板卡片上看得见——双副本漂移从此有了唯一的报警口。

## 涉及层
- [ ] 协议：`packages/protocol/src/protocol.ts` 的 `SessionSummary`（若有该类型）加可选 `protocolMismatch?: number`；`ConnectMsg.protocol`（:175）已存在，不改。**同轮把这条改动落到 fork 副本** `src/mcp/protocol.ts`（ticket 008 立的规矩）。
- [ ] 逻辑层：`src/session.ts` 的 `attach(ws, msg)`（:385 的 `summary()` 上面那族字段就在那儿赋值）读 `msg.protocol`：等于 `PROTOCOL_VERSION` → 不设字段；不等 → `this.protocolMismatch = msg.protocol`，并让 `summary()` 透出。**不 close、不降级、不影响任何工具调用**。
- [ ] 逻辑层：`src/hub.ts:169` 那条 `[ws] session ... connected:` 日志在不匹配时追加 `protocol mismatch: probe=<n> hub=<m>`（一行 stderr，不加新日志级别）。
- [ ] 逻辑层：`src/proxyHub.ts:60` 的 `protocol: 1` 字面量改成 `import { PROTOCOL_VERSION }`——否则将来 bump 版本号时，MCP proxy 那个假 session 会被自己判成 mismatch。
- [ ] UI 层：`lib/panel.js` 设备卡片（:251-266 的 `cards.map`）在 `s.protocolMismatch` 存在时于 row3 末尾加一句 muted 文案（例如「协议 <n> ≠ <m>」），沿用现有 `.muted` 样式；**不弹全局 toast、不打断操作**。
- [ ] 测试：`test/http.e2e.mjs`（现有假探针在 :44 发 `protocol: 1`）新增两断言，共用同一个假探针只改上报号：① 版本号一致时 session 里**没有** `protocolMismatch` 字段；② 报 `PROTOCOL_VERSION + 1` 时连接仍在（后续一次 `list_sessions`/工具调用照常成功）且该 session 带 `protocolMismatch: PROTOCOL_VERSION + 1`。

## 验收标准
- `node packages/whistle-plugin/test/http.e2e.mjs` 全绿，含上述两条新断言；断言里**不出现真浏览器**（spec US-19）
- 手工：`v2 start` + 现有 e2e 假探针报高版本号 → `curl 127.0.0.1:9527/api/sessions` 里该 session 有 `"protocolMismatch":2`；面板 `/` 卡片上肉眼能看到那行
- 版本一致时 `api/sessions` 输出与改动前逐字段相同（**不许**出现 `"protocolMismatch":undefined`／`null` 这类噪音）
- 不匹配时任何工具（`get_logs`/`get_network`…）仍返回正常结果，hub 没有主动 close 的记录
- `pnpm test:e2e` 0 FAIL

## 备注
「用新 hub 调一个已经发出去的旧页面」是这条判断存在的全部理由：硬断开等于把页面锁死在旧 hub 上，不检查等于把根因藏起来。所以形态只能是「能用 + 看得见」。
