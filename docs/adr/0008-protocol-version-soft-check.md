# ADR-0008: 探针与 hub 的协议版本只做软校验（不匹配就标警告，不断开）

日期：2026-10-06　状态：Accepted　关联：ADR-007

## 背景

`PROTOCOL_VERSION = 1` 早就在协议里，探针随 `connect` 上报，但 hub 侧从来没读它（只有 `proxyHub.ts:60` 自己填了个 `1`）。以前两端是同一仓库同一构建，不校验也没事；ADR-006/0007 之后探针和 hub 分别发版，页面里跑什么版本的探针就不受我们控制了——`examples/demo-h5/cdn.html` 演示的正是"引固定版本的 CDN 探针"。

## 决策

**hub 读上报的协议版本，与自身不一致时不断开连接，只在该 session 上打一个 `protocolMismatch` 标记，面板设备卡片与 `list_sessions` 都把它显示出来。**

## 理由

"用新 hub 调一个已经发布出去的旧页面"是这个工具的主用例，不是异常输入。硬校验（版本不匹配就 close）等于把公网/线上页面接不进来，为了一种本来就该降级看待的情况牺牲了主要场景；完全不校验（维持现状）则跨版本时面板默默缺字段、工具默默报错，排查的人看不出根因是版本。软校验把这件事从"猜"变成"看得见"，代价只是一个字段和一处展示。
