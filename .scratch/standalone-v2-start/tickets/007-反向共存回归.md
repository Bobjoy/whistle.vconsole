# 反向共存回归：daemon 先起，`w2` 转 proxy 复用同一 token

**Blocked by**: 003

## 目标
证明「standalone 先起、whistle 后起」不用写新代码就能走通：插件撞 :9528 自动转 proxy，并从 `hub.json` 读到**同一个 token**，注入与面板继续可用。

## 涉及层
- [ ] 数据层：`~/.whistle-vconsole/hub.json`（`{port, lan, token, updatedAt}`，只有 `j.port === port` 才采信）是唯一跨进程握手件。
- [ ] 逻辑层：预期**零改动**——`createBackend()` 已是 hub-or-proxy（`EADDRINUSE` → `ProxyHub` + `storedToken(port)`）。这片的工作是验证；若验证不过，改动只允许落在「daemon 正确写 `hub.json`」这一侧（003 的范围），不许新增第三个端口或 relay。
- [ ] 逻辑层：顺带钉住「不新增端口」——standalone 仍只用 :9527 + :9528，探针资源口 `GET :9528/html2canvas.min.js` 行为不变。
- [ ] 测试：`test/cli.e2e.mjs` 覆盖故事 12、13：`v2 start` → 假设备连 daemon（复用 `test/http.e2e.mjs` 的 `makeProbe` 思路）→ 子进程里模拟插件那一次 `boot()` → 断言面板能看到 daemon 侧已连设备、`/inject.html` 里 `serverUrl` 的 token 与 `hub.json` 一致、`GET 127.0.0.1:9528/html2canvas.min.js` 200。

## 验收标准
- `v2 start` 后模拟插件 `boot()` → 插件侧显示 proxy mode（不是失败退出）
- `/inject.html` 里的 `?t=` 与 `hub.json.token` 逐字符相等
- 全程只出现 :9527 与 :9528 两个监听端口
- 真 whistle 复核：`w2 start` + 假设备/手机 → 面板能看到 daemon 侧的设备

## 备注
这是 spec 里唯一「以验证为主、代码为辅」的一片，独立成片是因为它是 ADR-005「共存而非替代」的全部风险所在——过不了就说明单 owner 策略要重谈。
