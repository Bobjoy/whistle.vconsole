# 协议双副本落地：私有性、内联机制不变、两份起点一致

**Blocked by**: 003, 005

## 目标
确认「协议不发包、两侧各一份副本」这件事在两边都成立且可检查：本仓库这份仍靠构建期内联、不进任何 `dependencies`，两份副本从同一字节出发——之后 ADR-0008 的软校验才有资格当唯一报警口。

## 涉及层
- [ ] 依赖：`packages/protocol/package.json` 保持 `private: true`，且**没有任何包**在 `dependencies` / `devDependencies` / `peerDependencies` 里写 `@bobjoy/vconsole-protocol`（现状：`pnpm-lock.yaml` 里它是 `importer packages/protocol: {}`，零依赖、零引用）。
- [ ] 构建：Node 侧机制一字不改——`packages/whistle-plugin/tsconfig.json` 的 `paths` 仍直指 `../protocol/src/protocol.ts`，esbuild 构建期内联，发布物里不存在这个包（`npm pack` 后解包看不到 `vconsole-protocol` 目录）。
- [ ] 文件：`packages/vconsole/src/mcp/protocol.ts`（003 放的 fork 副本）与本仓库 `packages/protocol/src/protocol.ts` 起始字节一致；两边文件头各留一句「另一份在哪、改协议必须同轮动两处」。
- [ ] 测试：一条可复跑的比对命令（不写成测试文件，见 spec §6「不加一致性校验脚本」——这里只要求**本票验收时人工跑一次**并记录结果）。

## 验收标准
- `grep -rn "vconsole-protocol" --include=package.json --exclude-dir=node_modules --exclude-dir=vconsole .` 只命中 `packages/protocol/package.json` 自己的 `name`
- `packages/whistle-plugin` 的 `pnpm pack` 解包后：`dist/*.cjs` 里有协议常量的**内联字面量**（`PROTOCOL_VERSION`），但不存在 `@bobjoy/vconsole-protocol` 这个模块名被 require
- `md5 packages/protocol/src/protocol.ts packages/vconsole/src/mcp/protocol.ts` 相同
- `pnpm build && pnpm test:e2e` 绿（本票只动注释与文件头，机制没变，绿是回归而非新增能力）

## 备注
双副本是**主动接下的税**（ADR-0007 背景里量过三条路的代价后选的这条）。以后改协议：同一轮动 `packages/protocol/src/protocol.ts` + fork 的 `src/mcp/protocol.ts`，并且只在语义真的不兼容时 bump `PROTOCOL_VERSION`。
