# 递归克隆到两条启动形态全绿：pnpm 解析 + `probe.js` md5 对齐

**Blocked by**: 005, 010

## 目标
一个陌生人 `git clone --recursive` 之后什么都不用问，就能 `pnpm install && pnpm build && pnpm test:e2e` 全绿，且 whistle 插件路径与 standalone 路径服务的是同一个字节探针。

## 涉及层
- [ ] 依赖：`pnpm install` 在新拓扑下成立（`packages/vconsole` 作为 workspace 成员被解析；`@bobjoy/vconsole` 的 workspace 依赖不出 registry）。
- [ ] 构建：`pnpm build`（probe → vite → plugin 三段）在克隆目录里一次跑通。
- [ ] 逻辑层：不改任何代码——本票唯一的产出是「两条形态同源」这件事被证到。
- [ ] 测试：`pnpm test:e2e` 全绿 **190 项**（探针侧那 40 项已经在 004 落到 fork、010 从本仓库删净；如果这里还看到 230 或看到 `Cannot find module '../../probe/...'`，说明 010/005 的顺序被打乱了，先修顺序别改测试）。
- [ ] UI 层：`w2 install` + `w2 start` 路径下面板可打开、设备列表渲染正常（面板本身没动，这里只验 `:9527/probe.js` 换源后面板不炸）。

## 验收标准
- 全新目录 `git clone --recursive <本仓库>` → `pnpm install && pnpm build` 绿（无手写步骤）
- standalone：`v2 start` → `curl -s 127.0.0.1:9527/probe.js | md5sum` == `md5 packages/vconsole/dist/vconsole.min.js`
- 插件：`w2 install` + `w2 start` → **先摸一次 `http://127.0.0.1:8899/plugin.vconsole/`**（插件进程是懒 fork，不摸端口不起服务）→ 同上 md5 比对成立
- 两条形态各自 `curl -s 127.0.0.1:9527/api/sessions` 返回 200 且含 `"sessions"`
- `pnpm test:e2e` 0 FAIL

## 备注
插件与 standalone 共用 `createHttpService()`（ADR-005），所以 md5 只需验一次就能覆盖两条——但**两条都跑**，因为换源之后唯一可能出错的地方是构建期拷贝路径，而两条路径的 `dist/probe.js` 来自同一次 `build.mjs`。
