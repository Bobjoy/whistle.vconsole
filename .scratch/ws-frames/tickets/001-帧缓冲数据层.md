# 帧缓冲数据层

**Blocked by**: 无

## 目标
`Session` 拿到能按 `wsUrl` + 时间戳查询的 WS 帧环形缓冲，探针推下来的 `ArrayBuffer` 帧被 base64 兜底，重复推同一个 item 不会重复展开前缀帧。

## 涉及层
- [x] 数据层：`Session` 新增 `wsFrameBuffer: WsFrame[]`（FIFO 容量 2000）+ `wsUrlSeqCounter: Map<string, number>` + `expandedUpTo: Map<string, number>`（per item.id 记录已展开到第几帧）
- [x] 逻辑层：`Session.addNetwork` 里对 `requestType === 'websocket'` 的项，把**新增的** `item.messages`（对比 `expandedUpTo.get(item.id)` 已知条数）追加进 `wsFrameBuffer`，`data` 非 string → base64，`seq` 按 `wsUrl` 延续递增；超过 2000 从头部 shift
- [x] 查询层：`Session.getWsFrames({ wsUrl?, sinceFrameTime?, limit })` → `{ frames, nextSince, oldestSeq }`，按 `time` 过滤 + 取尾 N
- [x] 测试：对 `Session` 实例直接推多个 WS 项（同一 url 多次推全量 messages、不同 url、含一条 `ArrayBuffer` 帧），断言帧序正确、不重复、二进制是 base64、seq 按 url 延续、溢出后 oldestSeq 前移

## 验收标准
- `Session.addNetwork` 推一个 3 帧 WS 项 → `wsFrameBuffer` 长度 3，`oldestSeq=0`
- 再推同一个 item.id 但 messages 变 5 帧（探针全量替换）→ `wsFrameBuffer` 长度 5（前 3 帧不重复展开）
- 推一个 `ArrayBuffer` 帧 → 该帧 `data` 是 base64 字符串，`Buffer.from(data,'base64')` 能解回原字节
- 推 2001 帧 → 缓冲长度 2000，`oldestSeq` 指向第 2 帧（头部第 1 帧被挤掉）
- 两个不同 `wsUrl` 各推 2 帧 → `getWsFrames({ wsUrl: 'A' })` 只返回 A 的 2 帧
- `getWsFrames({})` 空 session 返回 `{ frames: [], nextSince: 0, oldestSeq: 0 }`，不 throw
