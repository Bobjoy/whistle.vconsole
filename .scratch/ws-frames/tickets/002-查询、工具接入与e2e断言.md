# 查询、工具接入与 e2e 断言

**Blocked by**: 001

## 目标
agent 通过 MCP 调 `ws_frames` 增量拉取 WS 帧，e2e 一次推帧里同时覆盖增量/过滤/会话隔离/空态/截断/二进制 base64/溢出 oldestSeq 全部断言。

## 涉及层
- [x] 逻辑层：`tools.ts` 加 `case 'ws_frames'`，走 `resolveSession(hub, opts)` + `session.getWsFrames`，`sessionId` 可选
- [x] 协议层：`mcpServer.ts` 注册 `ws_frames`，`inputSchema`：`sessionId?` / `wsUrl?` / `sinceFrameTime?`（number）/ `limit?`（number，默认 50），全 optional
- [x] 输出：走既有 `jsonResult`（60k 截断不变）
- [x] 测试（e2e fake probe，同一批推帧覆盖所有 US）：
  - fake 会话推一个 3 帧 WS 项 + 一条 `ArrayBuffer` 帧 + 撑满 2001 帧把缓冲溢出
  - 断言：
    - `ws_frames({})` 拿最近 N 帧 + `nextSince`（US-1）
    - `ws_frames({ sinceFrameTime: <上次> })` 不含已返回帧（US-1 不重不漏）
    - `ws_frames({ wsUrl: 'A' })` 只命中 A 连接（US-2）
    - `sessionId` 定向到某设备、不串（US-5）
    - 无 WS / 离线会话 → `{ frames: [], nextSince: 0, oldestSeq: 0 }`，不 throw（US-6）
    - 超大 `data` 帧 → 结果文本含 `…[truncated by whistle-vconsole]`（US-7）
    - `ArrayBuffer` 帧 `data` 是 base64，`Buffer.from(b64,'base64')` 解回原字节（US-3）
    - 2001 帧后 `oldestSeq > 0`，被挤头部帧不在返回里（US-4）

## 验收标准
- 以上 8 条断言全绿
